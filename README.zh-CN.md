# SillyTavern 性能实验室


## 部署前置条件

支持并测试 Node.js 主版本 **20、22、24**（Ubuntu/Windows CI）。`.nvmrc` 选择 24，以与较新的测试线一致；使用 `nvm use`，生产部署进一步固定经过验收的补丁版本。上游 `package.json` 的 `engines.node >=20` 保持不变，它不表示所有后续主版本都经过测试。

启用 `exclusiveDataRoot: true`，每个数据根只运行一个服务器。对真实配置运行 `npm run check:deploy -- --config ./config.yaml --data-root <数据根>`，要求退出 0、所有检查项通过（OK；INFO 是说明），无 WARN/FAIL。磁盘规则：可用空间不得低于 `max(1 GiB, 2 × 聊天+备份+回收区逻辑字节数)`；每个文件仅计一次，包括嵌套 `.recycle/`，不跟随符号链接。输出包含可用字节和回收区用量；`maxRecycleBytes` 默认 -1，回收区可持续增长。扫描或 statfs 失败会 WARN，检查不写文件。

`perf:lab` 强制 localhost，实际部署须单独核对 listen、白名单及认证。当前流式导出在整个下载期间持锁：卡住的下载可阻塞保存，若目录独占操作排队还可能阻塞同角色其他聊天。超出 localhost 暴露前，必须完成第四轮空闲超时及缩小锁范围修复。真实机器验收和整根备份仍是前置条件。

## 回滚

见[中文回滚手册](docs/ROLLBACK.zh-CN.md)：先停止新版并确认进程退出，再完整恢复包含隐藏目录的数据根备份；锁文件只能在确认所有者退出后逐个归档。

这是基于 SillyTavern 1.19.0 的研究分支，包含聊天可靠性、生命周期、启动和前端实验。
当前入口是 **`codex-improvements`**；`codex/sillytavern-1.19-sync` 是较早的集成基线。
其他候选分支和带日期的验收记录属于历史实验，本分支不是生产发行版。

安装项目依赖后，使用 Node.js 20 或更高版本，在仓库根目录运行：

```sh

npm run lint
npm run perf:lab
```

`test:perf` 包含 33 个测试文件，使用人工夹具，部分测试需要监听本地端口。
三个依赖独立历史源码的测试套件在 Git 或历史对象缺失时跳过；完整历史检出可启用这些比较。
`bench:perf` 仍要求历史 Git 对象。`lint` 检查项目源码语法，并对实验模块、脚本和测试启用部分规则，
并非完整的 recommended 规则检查。

`perf:lab` 固定运行于 **http://127.0.0.1:8780/**，数据和配置位于当前检出的
`.lab-data/`、`.lab-config.yaml`。每次启动都强制本地 IPv4、关闭 SSL、自动打开浏览器、

启动器打开 `exclusiveDataRoot`，服务器会创建 `<dataRoot>/.st-lab-owner.lock`，
第二个同样打开该标志的进程不能共用这个数据根。仅使用人工数据，同一个数据根目录只运行一个服务器进程。

`python tests/browser-performance-lab.py` 与 `python tests/browser-lifecycle-lab.py`

## CHANGES

近期修复覆盖角色编辑生命周期锁、关闭期间的请求与处理器排空、群聊历史路径校验，
以及每次启动时的隔离配置强制检查。关闭排空现在也会跟踪返回 Promise 的同步处理器，
并在 `SILLYTAVERN_DRAIN_TIMEOUT_MS`（默认 30 秒）后停止等待并继续关闭。
`numberOfBackups` 只限制可见备份个数；`backups.chat.maxRecycleBytes`（默认 `-1`，不限制）
可清理备份目录 `.recycle/` 中最旧的回收件。
刻意新建和改名目标可以复用已经不存在的退休名称；标记在发布成功后才回收，失败且路径仍不存在时会放回。普通保存仍会与仍退休的路径冲突。
角色合并（含批量）仍走 `withCharacterEdit`，改名仍在一次 `withPathLocks` 中占用卡片和聊天锁。
普通文件操作对父目录取共享锁、对文件取独占锁，同一目录中的不同群聊可以并行；
目录退役、重命名、删除和备份清理对目录取独占锁，后来的共享请求不能插到它前面。
进程内共享/独占路径锁始终有效，使用队列，不创建锁文件。需要的键在等待前一次预留。
嵌套调用不能等待已独占的键，也不能把共享锁升级为独占锁。
备份写入等待其来源预留及外层预留完成，不受无关锁持有者影响。
不支持多个服务器并发共用同一数据根。使用独占数据根所有权锁阻止第二个协作服务器启动。
`exclusiveDataRoot` 默认关闭，实验室启动器或配置可打开；使用同一数据根的服务器都必须打开。
所有权文件记录 pid、主机名、启动时间、随机 token，以及主机能够提供时的启动标识和进程启动时间。
Linux 读取 `/proc/sys/kernel/random/boot_id`，并用 `/proc/stat` 的 `btime` 换算 `/proc/<pid>/stat` 的 starttime。
Windows 的近似启动时间不作为回收仍存活 PID 的依据。仅缓存本进程的启动时间，外部 PID 每次重新探测。Windows 用 `os.uptime()` 记录近似的 `win-boot:` 时间（相差 120 秒内仍视为同一次启动）。
双方都有 `processStartMs` 时以它为准：相同则仍视为存活，即使 `bootId` 不同；不同则视为 pid 复用，即使启动戳相同。
只有双方都没有进程启动时间时才比较精确的 Linux 启动标识；只有一侧有启动时间则保持存活。
若两次本地采样相隔超过 2 秒且落在 120 秒窗口之外，之后的记录省略不稳定的 `bootId`，仍保留 pid、token 和 `processStartMs`。
进程启动时间来自不超过 200ms 的 PowerShell 探测；探测缺失或超时就省略该字段，此时同一次启动内的 pid 复用无法区分。
同一主机上，只要 `process.kill(pid, 0)` 认为 pid 仍存活（含 `EPERM`），且上述身份仍一致，后来的进程就拒绝启动。
身份对不上就视为 pid 被复用并回收。没有这两项身份字段的旧锁，在 pid 仍存活时保留。
已退出的同一主机所有者，或被复用的 pid，由恰好一个进程回收：它用 `O_EXCL` 创建 `<dataRoot>/.st-lab-owner.lock.reclaim`，
把过期的所有权文件改名到一边，核对内容后才删除，再用 `O_EXCL` 创建新的所有权文件。
回收标记按文件年龄过期，崩溃的回收者不会一直挡住下次启动。
其他主机留下的锁、符号链接和无法读取的文件都留在原地。
正常退出、`process.exit` 和未捕获异常只会删除内容仍与本次写入一致的锁。
跳过退出钩子的信号可能留下文件，同一主机上的下次获取会回收它。不需要编译器。
如果出现无法判断所有权的意外文件系统错误，启动会记录警告并继续；同一主机上的存活所有者仍然拒绝。
所有权文件是整个数据根的门闩。逐路径排除是上面临时目录中的锁文件，且只约束打开了相应标志的进程。未打开任一标志的进程仍可共用数据根。
本次补充修复角色写入失败仍返回成功的问题；
结构化克隆不可用或拒绝扩展数据时使用独立 JSON 快照，JSON 也无法序列化时保留已有存储；
历史测试源码缺失时明确跳过相关套件。

## 导演按钮（剧情快捷键）

### 打开方式

输入框左侧有一个 🎬 按钮（`directorButton`），紧挨在扩展菜单按钮后面。点击打开预设面板。面板处于预设列表且焦点在面板上时，数字键 1–9 使用前九个预设，Esc 关闭；点面板外面也会关闭。

斜杠命令是 `/director <预设名或序号> [文本]`，Quick Reply 可以用，例如 `/director 1 三天`。序号从 1 开始，纯数字始终表示序号。名称先按原文匹配，再忽略大小写；含空格的名称要加引号。这段文字只填进模板的第一个 `{{input}}`，其余已经写了默认值的输入用默认值，没有默认值的会再弹窗。

`/director` 的参数仍按 STscript 原来的规则处理。STscript 会在预设运行之前展开这段参数，所以命令里的宏可能已经变成展开后的文字。弹窗里手打的文字不走这条路径。扩展设置里「🎬 Director」的快捷键框默认是空的，留空就不注册全局快捷键；正在往输入框里打字时也不会触发。

### 三种模式

| 模式 | 是否写入聊天 | 模型能否看到 | 上游实现 |
| --- | --- | --- | --- |
| narrator（旁白） | 是 | 能 | `/sys`（`sendNarratorMessage`） |
| comment（备注） | 是 | 不能 | `/comment`（`sendCommentMessage`） |
| instruct（导演指令） | 否 | 能，规则见下方生命周期 | 待生效走 `/inject`；已绑定的沿用走 `setExtensionPrompt` |

旁白和备注调用的是这两个命令已经注册的回调，正文不经过斜杠解析器。旁白写入聊天，模型能看见。备注也写入聊天，并且 `is_system` 为真，界面上的说明是「仅自己可见」。

导演指令不写成聊天消息。待生效的一条调用上游 `/inject`：`ephemeral` 为 false，`position` 为 chat，`depth` 为 0，`role` 为 system，`scan` 为 false。记录在当前聊天的 `chat_metadata.script_injects` 里，id 形如 `director-<uuid>`，并带 `directorEphemeral: true`。这次调用会通过 `setExtensionPrompt` 放进扩展提示词。传入的 `ephemeral` 是 false，所以上游在生成结束或停止时会把这条记录留着。

已经绑定、要在 swipe、重新生成或续写里沿用的那一份，由生成拦截器 `director_rebind_interceptor` 调用 `setExtensionPrompt`。键是 `script_inject_director-bound`，位置同样是聊天内、深度 0、system、不参与世界书扫描。这份副本不写入 `script_injects`，所以成功结束后不会被当成待生效指令消费，也不会留到下一次无关的生成里。

### 预设

默认有 8 个，顺序就是数字键和 `/director` 序号：

1. ⏩ 时间跳跃（旁白）：`——{{input:过了多久？|一段时间}}后——`
2. 🎬 场景切换（旁白）：`【场景：{{input:新的地点}}】`
3. 📖 旁白（旁白）：`{{input:旁白内容}}`
4. 🌙 新章节（旁白，章节起点）：`第{{chapter}}章　{{input:章节标题}}`
5. ⚡ 突发事件（旁白）：`（突然，{{input:发生了什么}}）`
6. 🎭 导演指令（指令）：`[导演指令：{{input:你希望接下来怎么发展}}]`
7. 🔁 推进剧情（指令）：`[导演指令：推动剧情向前发展，引入一个新的变化，不要重复之前的情节。]`
8. 📝 备注（备注）：`{{input:写给自己的备注}}`

面板页脚「⚙ 管理预设」打开扩展面板（Extensions）里的「🎬 Director」。那里可以添加、删除、拖动手柄或用上移、下移排序，也可以导入 JSON、导出 JSON、恢复默认。导入整份替换；校验失败则保持原样。文件须为 `{"version":1,"presets":[…]}`。每项只能有 `id`、`icon`、`name`、`mode`、`template`、`isChapter`、`autoGenerate`。`mode` 只能是 `narrator`、`comment`、`instruct`。最多 50 个。

「插入后自动生成」（`autoGenerate`）默认关闭。打开之后，这次插入成功才会再去生成。

### 模板

`{{input:提示|默认值}}` 会弹出输入框。提示是标签，第一个 `|` 后面是默认值，可以不写默认值。点取消则这次什么都不插入。一条模板可以有多个输入。

`{{chapter}}` 是当前聊天里已有章节标题的条数再加 1。数字在使用时现算，不写进消息。

`substituteParams` 只作用于模板里原有的文字，并且按 `{{input}}` 和 `{{chapter}}` 切开之后逐段调用，一个宏不能横跨这些占位符。弹窗里输入的 `{{char}}`、`{{user}}`、`{{random::a,b}}`，以及看起来像 `{{input:…}}` 或 `{{chapter}}` 的文字，都原样进入结果。模板自己的 `{{char}}` 会展开成角色名。

还有两处会在别的时候展开，这次没有改掉：

- `/director <预设名或序号> [文本]` 的参数仍按 STscript 展开。保持原样的是弹窗输入，不是这条斜杠参数。
- 旁白和备注保存到磁盘的 `mes` 保持输入原文。之后某一次生成组装提示词时，`PromptManager.preparePrompt` 仍会对已经保存的聊天消息调用 `substituteParams`，所以这些原文里的宏可能在那一次请求里被展开。`{{setvar}}`、`{{roll}}`、`{{random}}` 每次生成都会重新求值，不要把它们写进旁白或备注。导演指令放进请求体的那一段会保留输入的宏：组装期间如果文字里还有宏，会暂时换成内部占位，请求成型后再换回原文。这不是给用户用的转义写法。

### 章节

章节标记在该消息的 `extra.director` 上，包含 `id`、`preset` 和 `chapter.title`。不保存章节序号，不写入 `chat_metadata`，也没有单独的章节文件。同一条消息的每个 swipe 都会在 `swipe_info` 的 `extra.director` 里带上一份，切换 swipe 或重新载入后仍在。

章节号按整段聊天里带标题的消息顺序现算，删掉中间一章后后面的号会重排。消息菜单「设为章节起点」可以标记任意消息，标题框预填该消息首行；再点一次取消。弹出菜单「📖 章节」列出序号和标题，点击跳到该消息。目标还在当前已加载范围之前、并且距离超过 500 条时，会先请你确认。

### 导演指令的生命周期

```text
pending（待生效）
    │  GENERATION_COMPLETED，且请求体里包含这条指令
    ▼
bound（已绑定，chat_metadata.director.boundInstruct）
    │  下面的清除条件
    ▼
删除
```

只有 `GENERATION_COMPLETED`，并且组装好的请求里确实包含这条指令的文字，才算用掉。接口报错或中途停止时，待生效的指令还在，绑定也不变。用掉之后，如果这次生成的类型是 `normal`、`swipe`、`regenerate` 或 `continue`，文字会记到当前聊天的 `chat_metadata.director.boundInstruct`：`id`、`text`、`slotIndex`、`prevFingerprint`、`boundAt`。`slotIndex` 是这次产生的 AI 消息在 `chat` 里的下标。`prevFingerprint` 由前一条消息的 `is_user`、`name` 和 `mes` 算出，不用 `send_date`。绑定只放在这份聊天元数据里。`quiet` 和 `impersonate` 不会把待生效指令放进这次请求，也不会把它用掉或写成绑定。这次生成会从扩展提示里拿开这些指令，并在 `GENERATION_ENDED` 或 `GENERATION_STOPPED` 时按原文字放回。如果提前返回或出错而没有发出这两个事件，则在下一次非 dryRun 生成开始时恢复。切换聊天时直接丢弃旧聊天的屏蔽状态，因为新聊天已经重新建立了自己的扩展提示。

绑定之后，对这条消息做 swipe、重新生成（类型 `regenerate`）或续写（`continue`），会再次带上同一段文字。这次带上的副本不会被消费，所以连续滑几次都还在。有待生效指令时只发送待生效的那一条。普通发送、`impersonate`、`quiet`，以及类型为 `normal` 的生成，都不会沿用绑定。群聊里下一个角色的自动发言，还有群聊的重新生成，上游类型都是 `normal`。

绑定在这些情况下删除：

- `MESSAGE_SENT`：发出一条消息。用户消息会清掉绑定。旁白和备注的插入也会发出 `MESSAGE_SENT`，所以也会清掉。
- `MESSAGE_RECEIVED`：绑定位置之后又写入了一条已经确定的消息，也就是收到的 id 大于 `slotIndex`。例如群聊里下一个角色发言。swipe、续写和重新生成写回的仍是原来那个位置，不会因此清除。
- `MESSAGE_DELETED`：删完以后聊天长度小于等于 `slotIndex - 1`，或者前一条消息的指纹已经对不上，或者绑定的那条 AI 消息本身被删掉。重新生成开头那一下临时删除不会清除。
- 准备对 `swipe`、`regenerate` 或 `continue` 重新注入时，位置对得上，但前一条消息的指纹对不上（例如那条用户消息被编辑过）：不注入，并清除绑定。
- 一条新的待生效指令被成功用掉：它替换原来的绑定。
- 状态提示上点 ✕，或在全文窗口里点「清除」。

切换聊天不会清除。每个聊天各自保存自己的绑定，切回来还在。

状态提示是 🎬 后面的按钮 `#director_instruct_chip`，带 `aria-label`。没有指令时隐藏，不占 Tab。待生效是橙色（`#c45c12`），文字是「🎭 待生效：」加上指令的前 16 个 Unicode 码位。已绑定是灰蓝色（文字 `#5c6b80`），文字是「🎭 重生沿用：」加上同样的预览。只有超过 16 个码位才加省略号。悬停的 `title` 和 `aria-label` 是全文。点文字会打开窗口，里面只有「关闭」和「清除」，不能编辑。点 ✕：待生效则取消这条指令，已绑定则清除绑定。

### 已知限制

- 群聊里的重新生成（`regenerate`）不会沿用已绑定的导演指令，这是已知限制：上游把它当作 `normal` 生成，群聊里下一个角色的发言也是如此。
- 模板中带副作用或随机性的宏，例如 `{{random}}`、`{{roll}}`，以及 `{{setvar}}` 等计数器类宏，每次生成都会重新求值，包括 `swipe` 和 `regenerate`。旁白和备注里的这些宏也会在之后每次生成组装提示词时重新求值，避免在这些消息中使用。

## 流式输出

### 优化的流式渲染

「使用优化的流式渲染」（`optimized_streaming`）默认打开。打开时：

- DOM 更新按帧合并，一帧最多画一次，并且画在这一帧之后的任务里，避免在动画帧回调里做格式化把这一帧拉长。刷新仍受 `streaming_fps` 限制。这个上限在用户设置的 Chat/Message Handling 里，标签是 Streaming FPS，默认 30。
- 第一块可见内容马上绘制，可见的推理文字也一样，不等这一帧。
- 其后用 `isEqualNode` 比较节点，只替换从第一个不同节点起的尾巴。
- 向上滚动（滚轮、触摸、方向键或向上拖）会停止跟随。距底部不超过 40px 才算还在底部。停止后，输入框上方靠右出现「↓ 新内容」（`chat_new_content`）。点它回到底部并恢复跟随。生成结束后，只要还没回到近底，这个按钮就还在。
- 遵守 `auto_scroll_chat_to_bottom`。它在同一组 Chat/Message Handling 里，标签是 Auto-scroll Chat。关掉之后，流式过程中不会自动滚动，只能用上面的按钮回到底部。
- `STREAM_TOKEN_RECEIVED` 仍然每一块派发一次，发生在这次 DOM 写入之前。

扮演（`impersonate`）和 Stream Fade-In（`stream_fade_in`）即使这个开关开着，也仍是同步绘制。

### 回退开关

开关在用户设置（User Settings）的 Miscellaneous 里。复选框 id 是 `optimized_streaming`，旁边的文字是「使用优化的流式渲染」，对应 `power_user.optimized_streaming`，默认勾选。

关掉之后，流式 DOM 走原来的同步路径：不再按帧合并，也不再放到帧后的任务里。导演按钮和这个开关无关，关掉流式优化不会改变导演指令。

某个扩展在流式过程中显示不对时，把这个开关关掉。常见的情况是它在 `STREAM_TOKEN_RECEIVED` 里读气泡 DOM，并且期望每个 token 当时已经画上屏幕。

### 已知限制

帧耗时 p95 是 16.8ms，也就是 60Hz 刷新下能测到的下限。

「超过 33ms 的帧占比下降至少 50%」在后来的复测里没有达到：大约只下降了 27%，置信区间包含 0。

在 `STREAM_TOKEN_RECEIVED` 的回调里读取 DOM，看到的内容可能比这次事件给出的文字落后一帧。格式化偏慢、刷新再隔帧时，还会更落后。

按格式化耗时调整刷新频率已经做了，在「使用优化的流式渲染」打开时的那条路径上。最近 6 次格式化耗时的平均值超过 8ms，刷新会再隔一帧；超过 16ms 再隔一帧。最后一块、停止和出错仍然马上完整刷新，第一块仍然立刻绘制。这是流式 DOM 合并那一版里就有的逻辑。没有再单开一轮后续调整，因为主场景帧耗时 p95 已经是 16.8ms（60Hz 的下限），格式化也不是长任务的主要来源。
