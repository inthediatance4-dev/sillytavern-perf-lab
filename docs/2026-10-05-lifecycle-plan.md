## 本轮优先项及契约

1. 保存、重命名、删除、角色目录与群聊相关操作统一预订多个路径锁；锁按规范路径去重，Windows 大小写别名使用同一锁。锁只协调一个 Node 进程。
2. 保存还检查持久的文件/目录退役标记。旧名称不复用；迟到请求包括 force 保存返回独立的生命周期冲突，前端提示重新加载或另存，不自动强制覆盖。
3. 重命名和导入先完成临时文件，再排他发布，避免覆盖已有目标或展示半份文件。原聊天、删除内容、导入上传及失败候选均进入应用 `.recycle`，不永久删除。
4. 导入先解析并验证，成功后再回收上传；不同历史使用唯一名称，失败保持可恢复原件。
5. 两类 tokenizer 在成功加载后发布实例，同一实例冷启动请求共享一次初始化；失败返回既有 null 结果，后续允许重试。昂贵模型工厂以人工替身隔离验证。

- 暂存白名单源码、测试和说明，检查 `git diff --cached --check`；配置、聊天、密钥、模型、依赖、浏览器缓存及测试结果均不提交。
- 交付前再次核对两个旧工作区的全部跟踪文件及 Git 状态，保留新分支与证据；不合并、不推送、不部署。

## 明确边界

持久标记会保留被退役的名字，需要另存一个新名称。同角色目录的生命周期锁会串行相关聊天操作；其他角色/用户仍可独立执行。应用回收区不会自动释放磁盘空间。

本轮不承诺跨进程/分布式锁，也不承诺目录退役、排他发布、回收及 marker 构成一项全崩溃原子事务。异常中断可能留下需人工检查的标记和可恢复候选，不能通过删除原件来简化恢复。

真实模型延迟、WASM 失败时的资源释放、transformers 活跃任务与 dispose 的协调、角色列表/统计缓存、向量索引并发、缩略图与缓存容量仍需后续独立验收。
