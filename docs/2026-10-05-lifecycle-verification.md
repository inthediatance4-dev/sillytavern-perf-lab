## 改动与结果

保存、读取、重命名、删除和相关目录操作现在共用多路径队列。退役标记持久保留，force 不能复活已删除/改名路径；角色改名继承原目录内已退役的聊天名称。已有聊天和头像不被改名/新建目标覆盖，导入先验证内容，多历史使用不同名称。相关原件和失败候选放入应用 `.recycle`。

单聊和群聊保存冲突返回失败状态。选择保留页面不会在插入消息或 token backfill 链中继续自动重载；消息在本地重绘。下载内容在保存请求前冻结，按提交序号识别新旧；响应乱序、切换聊天及 Popup 完成间隙均有测试。同聊天合并等待中的较新快照，不同聊天串行展示独立弹窗。

SentencePiece 和 Web tokenizer 完成初始化后才公开实例，同实例冷加载共享一次 Promise；失败允许重试。真实模型验收仅使用内置 llama 和 llama3，没有下载模型或调用生成服务。

## 剩余问题与使用代价

- 锁只保护一个 Node 进程；硬链接需要同卷/文件系统支持。Linux、只读文件、网络盘、生产负载、真实插件及强制断电未验证。目录/多文件操作不是一项全崩溃事务，整组删除失败可能部分退役，原件留在回收区，需要人工核对。
- 退役名称不复用，同角色目录和同用户群聊目录的相关保存会串行；回收区和标记继续占磁盘。本轮不据此声称整体吞吐量提高。
- 其他头像编辑/合并入口可能重建旧 PNG，但不会清掉聊天目录标记；启动迁移、BYAF 全资源事务、书签 metadata 回滚与所有旧调用者对 false 的处理尚未覆盖。
- 同名多窗口编辑仍使用原有完整性身份，尚未引入内容版本 CAS；不能声称避免了所有后写覆盖。
- Popup 已处理序号表只留数字，不存聊天正文，仍没有长期容量策略；导出等旧链可能忽略失败返回值。
- 远程 tokenizer 下载、跨 wrapper 下载去重、失败 WASM 资源释放、nerdstash_v2 路由及 transformers 活跃任务 dispose 尚未修复或证明。

后续优先项为向量索引并发更新一致性及 batch 契约。独立合成复现已记录：WebLLM/KoboldCPP 21 输入产出 63 结果；实际 Vectra class 在内存模拟文件系统中两个成功提交只保留后者。它们是有界机制证据，不是线上事故或真实用户数据损失的证据。TTL、角色统计、图片与缓存成本也已列入独立审查。
