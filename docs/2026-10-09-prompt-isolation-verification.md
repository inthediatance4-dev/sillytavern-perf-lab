## 修改与理由

旧提示词读取在存储等待之后直接覆盖全局缓存；后来的聊天已打开，先前读取或错误仍能覆盖新缓存。关闭在读聊天也会把尚未完成的空缓存保存到旧记录上。修改为模块内请求所有权和可保存状态：字符/群聊在准备和首条问候保存之前预留请求，存储结果先留在局部，过期读取不改缓存、不发 LOADED。成功读到不存在的记录可保存空数组；真正读取失败时缓存不可保存，直到成功重读，保护已有记录。

清理先取消旧读取，保存期间保留原快照和文件名；保存结束后只有仍持有所有权的清理才能清空缓存和聊天模型。对有文件名的聊天清理后，空缓存仍不可保存，避免“新聊天”连续清理两次覆盖旧提示词。正常保存和书签另存仍兼容原有接口、事件及格式；成功接口仍为 void，取消返回 false。数组快照仅浅拷贝，不保证嵌套对象不可变。

群聊加载取消结果传到打开入口及欢迎页，阻止关闭后的旧操作继续激活、保存设置或清理 HOME。入口序号和对象/文件/选择校验覆盖等待清理、同组重入；渲染后及终止事件后校验阻止旧加载报告成功。保留已选群返回 false 时仍可切换另一段历史的旧行为，并检查忙碌状态。本轮不重做完整群聊渲染事务，不宣称已开始的问候、渲染或扩展监听器副作用全部可以撤销。

## 交付边界与剩余问题

交付只含白名单源码、测试及说明；配置、运行数据、依赖、缓存、模型、用户资料均不进入暂存和增量包。根代理检查普通及暂存 whitespace、暂存清单、明确新增源码范围的密钥字面量启发式；这不是完整历史安全审计。恢复验收要求完整 Git bundle 实际克隆并逐一比对 Git blob、原工作区、ZIP 和 SHA-256，最终结果放在 `delivery-verification.json`、`final-completion-verification.json`。

实际 IndexedDB 读取失败时，新生成的提示词检查条目可能暂时不持久化，需成功重读恢复。其他直接历史切换、生成或明确删除流程的异步竞态，以及已经执行中的第三方事件副作用，仍需单独审查。此前富文本同步构建和布局开销未改变。实验环境既有外部 st-memory 更新失败、message.mp3 404、依赖 junction 的 WASM 缩略图权限错误保留，不放宽路径保护，也不据此判断线上故障。
