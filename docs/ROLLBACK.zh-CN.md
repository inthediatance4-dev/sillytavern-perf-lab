# 回滚手册

**推荐回滚目标：`9293a4e`**（新版仍在运行时它会拒绝启动）。`48a153e` 没有数据根所有权锁，新版存活时也能启动并共享数据根（演练实测），仅作最后手段，并且必须先按第 1 步确认新版已完全退出。

每次升级前先停机，备份**整个数据根**（包括隐藏目录），并记录应用提交、Node 版本、配置及备份位置。回滚目标：`9293a4e` 是第二轮合并前版本；`48a153e` 是 1.19 同步基线，比前者更早。两者已有退休保护；`9293a4e` 有数据根锁，`48a153e` 没有数据根所有权锁。两者都缺少后续 v2 身份校验、启动对账、只读检查工具及流式导出等可靠性修正；不能假定旧版可安全处理新版留下的全部状态。工作树演练已发现 `48a153e` 在 NEW 持锁存活时仍能监听，不能依赖它自动阻止误启动；`9293a4e` 在同场景拒绝启动。此安全门未通过，部署前须人工保证 NEW 完全退出。

1. 先停止 NEW：关闭服务管理器自动重启，向实际服务器进程发送正常停止信号（终端 Ctrl+C；服务使用其停止命令），等它退出。检查日志没有 `Shutdown incomplete`，并核对监听端口已关闭。不要用强制退出掩盖排空卡住；有未完成操作时保持停机并排查。
2. 确认所有使用该根的服务器和外部写入都已停止，再保留当前数据根作为故障副本（重命名到带时间戳的归档路径）。将升级前备份完整复制到原位置，**不要合并覆盖旧目录**。Linux 示例：`cp -a /backup/data-root /srv/data-root`（目标须不存在）；PowerShell 示例：`Copy-Item -LiteralPath 'D:\backup\data-root' -Destination 'D:\app\data-root' -Recurse`（目标须不存在）。确认 `.chat-lifecycle/`、`.chat-staging/`、`.recycle/` 及其他隐藏文件均已复制，核对文件数量、内容和权限。绝不永久删除原根或回收件。
3. 在独立应用检出中安装选定提交的依赖，使用记录的配置、数据根和已测试 Node 主版本。每个根只允许一个进程，在支持的版本中启用 `exclusiveDataRoot: true`（48a153e 不支持，必须由运维确保根独占）。先按下述方法处理确实过期的所有权锁，再启动旧版；不要绕过身份校验。
4. 启动前和启动后运行 `npm run check:integrity -- --data-root <数据根>`。旧提交没有该命令时，从保留的新版工具检出运行 `node scripts/check-integrity.mjs --data-root <数据根>`。检查是只读的；退出 1 表示有发现（含非空回收区），2 表示检查错误。逐项核对，不能靠批量清空标记消除发现。核对聊天列表、保留聊天和删除记录没有复活，再开放访问。

## 锁拒绝时的人工处理

Windows 从浮点到 BigInt 的启动时间换算可能相差 1ms，从而拒绝启动；Linux 的 v2 记录可能让旧版无法确认身份而拒绝。均应保守停机，不修改记录字段来通过校验。

读取报错路径 `.st-lab-owner.lock` 的 `hostname`、`pid`、`token` 并保存原件。确认是在记录对应的主机上操作。Linux 用 `ps -p <pid> -o pid,lstart,args` 和 `kill -0 <pid>`；只有明确 ESRCH/进程不存在才算已退出，EPERM 不算。Windows 用 `Get-Process -Id <pid> -ErrorAction Stop`（仅“进程不存在”可算退出；访问拒绝或探测失败不算），并用 `Get-CimInstance Win32_Process -Filter "ProcessId = <pid>"` 核对命令行和 CreationDate。再核对服务管理器、其他 Node 服务器和监听端口；PID 已复用或身份仍不明时保留锁并排查，不能因“看起来不是它”直接移锁。

只有确认所有者 PID 已消失、该根没有任何活跃进程、自动重启已禁用后，重新读取锁并确认内容未变，将**这一份锁**重命名为 `.st-lab-owner.lock.manual-<时间戳>`（或移动到 `.recycle/` 的独立归档目录），保留审计证据，再重试启动。绝不在进程存活时移走锁，也不批量处理 `.chat-lifecycle/` 或退休标记。

## 上线后第一周

每天在停机的一致视图下运行一次 `check:integrity` 并保存结果；监控 `LockOrderError`、`Shutdown incomplete`、启动扫描各类发现数量及其增长。异常时保留证据并暂停部署。固定 Node 主版本及补丁版本：CI 覆盖 20、22、24 × Ubuntu/Windows；推荐 `.nvmrc` 的 24，保持与较新的测试线一致，部署前记录具体补丁版本。不要部署未测试的主版本。真实 Windows 浏览器、停止及回滚验收仍需在部署机器完成。
