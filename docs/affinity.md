# 好感度记忆

好感度随「命运之笔」启用，设置抽屉只有开关和整理频率。默认每 10 条有效助手回复整理一次，可改为 5 条。关系分数仅供内部使用，范围为 -100…100；没有分数显示、角色面板或查询命令。

## 接入与隔离

- `director_rebind_interceptor` 在提示组装前调用 `affinity.prepare`。最多注入五项当前角色的事实、未决约定和弱倾向；明确低于当前对话与个人边界，不要求恋爱或亲密。
- 完整记忆先以保护宏分隔符与换行的 frame 加入当前 interceptor 的请求副本，参与原生上下文预算；不安装共享 extension prompt，也不参与世界书扫描。`GENERATE_AFTER_DATA` 根据该次原生生成类型恢复字面文本，未知 frame 整段清除。并发 quiet、impersonate 不获取记忆，也不清掉普通生成的计数归属。
- `MESSAGE_RECEIVED(messageId, type)` 只登记候选；`GENERATION_COMPLETED` 才验证同一 chat、metadata、消息对象、最终文本和当前已保存的 swipe。`GENERATION_ENDED` 是 UI 解锁信号，流式时可早于消息保存，不能用来计数。
- 继续生成更新原逻辑消息，不新增计数；重生成保留被替换逻辑消息的凭据。群聊每个成功回复累计一次，以规范 avatar 区分同名角色，等 `GROUP_WRAPPER_FINISHED` 后才启动整理，不按角色分别发评估请求。
- 旁路使用 `generateQuietPrompt({ isolated: true, jsonSchema, quietPrompt, signal, maxOutputTokens })`，沿用当前主提供方；没有单独模型配置。单次输出额度为模型上下文的四分之一，上限 2048 token、下限 128；只作用于该请求，正文回复设置与 `TempResponseLength` 不变。隔离路径使用 raw API 的本地 controller，并跳过正文提示及 CC/TC 参数修改事件，避免消耗别的请求的长度恢复钩子。新主生成、关闭功能或切聊天只取消旁路自己的 signal，正文不等待它。
- 所有评估和保存工作均脱离正文事件 promise。失败不向正文抛出；控制器不把原文、响应或密钥写入错误日志。

## 存储合同

`chat_metadata.director.__affinity` 的版本为 1，保存宿主 scope UUID、单调 ID、已接受消息计数 `issued`、已尝试批次游标 `cursor`、当前证据和短期归档。其他 director 元数据不被覆盖。未知版本不自动重置。

每个可引用的非系统消息及其各 swipe 的 `extra.__affinity` 保存很小的 `{ version, scope, id, receipt, evaluated? }`。`id` 是宿主生成的逻辑消息 UUID；`receipt` 只在关联的生成成功后分配。历史消息、用户消息与手工插入消息初始没有有效回复计数。消息正文、所选 swipe 和 fingerprint 与凭据一起校验；模型不能自行指定 ledger ID 或分值。

页面内最多保留 128 条尚未确认落盘的成功凭据，用于衔接完成事件、异步保存与同聊天的原生重载。恢复前逐项核对聊天、scope、规范角色、索引、原文、swipe 与逻辑标记；原文改变或身份冲突即撤销缓存，切回旧分支也不会恢复它。已由原生保存写入的新 `evaluated` 不会被旧缓存覆盖，关闭后重载再启用也会先恢复有效凭据。保存绑定原聊天及加载代次，加载中的空聊天窗口不能授权写入。

后台最多一个请求在途，后续工作从当前聊天的消息凭据导出，按最早批次处理，不用“只留最新请求”的队列覆盖中间批次。被取消、无效或失败的批次不立即循环重试；未整理的证据可与下一个真实批次一起再次检查，每次最多额外带入最早二十条。没有新批次时，手工编辑只撤回失效证据，不额外调用模型。

`MESSAGE_EDITED`、`MESSAGE_UPDATED`、`MESSAGE_SWIPED`、`MESSAGE_SWIPE_DELETED`、`MESSAGE_DELETED` 和群成员变化均重建当前投影。源消失或 fingerprint/swipe 改变会撤回对应事实与分值；删除兑现结果只撤回结果，原承诺仍在。已撤回的分支证据不会在切回旧分支时凭空恢复，可随下一批有效回复重新整理。

## 评估合同

- 只接受严格校验的 JSON 对象或完整 JSON fence，拒绝额外字段、原型字段、越界字符串、未知角色与虚构引文。引文必须逐字存在于绑定消息，最长 180 字符；事实最长 160 字符。
- 角色 owner 使用当前角色或群成员的规范 avatar，玩家固定为当前聊天的 `player`。模型 actor/recipient 只能是 `character`、`user`、`other`。某角色的发言不能替另一角色增加态度。
- 普通经历、照顾、礼物、边界和未决承诺均可记为事实，本身不加分。仅明确的角色态度或有承诺锚点的已知完成结果可产生变化；不使用情节文本正负面的正则规则。
- 轻微正／负变化为 +2／-3。重大正／负变化为 +5／-8，必须对原始引文再做独立核验；核验包含实际来源、结果、确认引文及归档中的承诺锚点。超出单次预算时分组顺序核验，同时只发一条请求。单项连独立核验都无法容纳、未确认或核验失败时保持零分，不降级成轻微变化。角色离场会取消旧工作，不再为其追加核验。
- 承诺 ID 由宿主单调分配；兑现必须同时绑定原始承诺和因果上更晚的不同结果证据。结果和确认的先后按首次接受的规范引文完整范围判断，缩短别名不能制造先后关系。角色自己履约也会关闭约定、释放未决容量，但不加好感分。未来打算、重述承诺和未知结果不能当作完成。
- 去重依赖 owner、逻辑消息、所选 swipe、fingerprint 和原文区间。改变引文宽窄不能对同一段证据重复计分；不重叠的独立证据仍可分别记忆。已保存的旧别名会合并到最早宿主 ID，并重绑有效承诺依赖。同一已兑现承诺不能再次奖励。
- 角色未知或不确定是否知情的证据可留在账本，但仅 `knownToCharacter=yes` 的证据可进入该角色的提示，避免把玩家秘密变成角色知识。

当前证据最多 160 项／80,000 JSON 字符、归档最多 80 项／50,000 JSON 字符，总承诺锚点最多 64 个。未决约定固定保留；容量不足时拒绝新增约定，已决旧记忆按依赖成组渐忘，容量回收不能重新打开承诺。若外部损坏的元数据已包含超额未决集合，保留原集合并拒绝新增，不静默删约定。选入正文的记忆最多五项。评估输入也有摘录预算，超长消息仅提供部分字面原文，未展示的中段不能保证被发现；这不会截断或修改聊天正文。

评估输入按当前提供方的原生 tokenizer、请求实际格式和独立输出预留计算预算，另保留结构化 schema 及格式余量；不再把固定字符数当成 token 预算。裁剪只影响本次请求视图，不删除持久账本，也不把完全省略的旧上下文标为已整理。预算不足时不发超限请求；取消也能释放正在等待 tokenizer 的工作。

隐藏指常规界面不展示分数与等级，并非加密：聊天元数据、导出与模型请求中仍有关系证据。

## 离线验证

新增状态、生命周期和提供方隔离测试均已加入 `npm run test:perf`。状态和生命周期测试直接导入生产模块、使用项目 EventEmitter；提供方测试执行真实 quiet/raw 函数，以本地 fixture 替代 I/O。测试中的结构化响应是明确的测试输入，不表示真实模型效果。

补完验证：好感度四文件 160/160、Director/reasoning 427/427；完整回归 1226 通过、0 失败、20 项按现有平台或权限条件跳过。真实浏览器合成 provider 验收及第三方共存范围见 [补完报告](reviews/2026-11-06-affinity-completion/README.md)。

本次开发不调用真实 LLM API，不读取任何密钥，不做 live 测试。完整验证结果以实际运行的测试日志为准。
