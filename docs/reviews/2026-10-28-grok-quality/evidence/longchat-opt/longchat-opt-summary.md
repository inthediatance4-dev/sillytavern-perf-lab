## P4：会话中回收顶部 DOM

- **提交：** 8fff4fb（只包含证据与测量工具改动，产品代码未改）
- **CI：** run 40799009162，6/6 通过
- **闸门（n=7/组）：** 不加载更早消息时发送中位数 399 ms（DOM 1.4 万节点）；加载 10 批后 1487 ms（DOM 8.8 万节点）。比值 **3.728**，CI [2.320, 4.315]，> 1.5，触发 P4。
- **实现并测量**（始终开启，发送前保留 5×截断条消息的 DOM）：DOM 87,858 → 43,684 节点；发送 1487 / 1705 → **1060 / 2215 ms**（n=5）。中位数比 0.713，CI **[0.514, 1.772]** 含 1；p95 变差；目标 <598 ms 未达到。
- **决定：不合并产品改动。** 收益未证实，而且每次发送都会改变可见行为（已加载的历史离开 DOM、合成的 show-more 按钮）。diff 与单测保存在 `p4-decision/rejected/` 仅供参考。
- **下一步建议（未实现）：** 加载更多历史后发送的成本仍随 DOM 增长，应先对这一路径做 profile（keyboard 剩余开销、`refreshSwipeButtons`、保存前的整聊天序列化），而不是裁剪 DOM。
