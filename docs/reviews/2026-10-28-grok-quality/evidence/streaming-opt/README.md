# Streaming measurement lab

S0 measures existing behavior. The only runtime changes are read-only timing probes, enabled by `?stPerfStreaming=1`, read once at module load. Disabled probes perform boolean checks only: no per-update clocks, objects or callbacks. Enabled records use a bounded 60,000-entry buffer exposed as `window.__stStreamingPerf`.

```sh
node scripts/fake-openai-endpoint.mjs --port 8999 --tokens 3000 --rate 200 --seed opus-streaming-s0 --reasoning
node scripts/measure-streaming.mjs --base HEAD --head HEAD --scenario main --runs 10 --output .evidence/streaming-selfcheck
node scripts/measure-streaming.mjs --matrix --runs 7 --output .evidence/streaming-baseline
```

`--timing-overlay <patch>` applies an explicit instrumentation-only patch to both archived products and copies the shared timing module. Its hash is retained in invocation.json. This supports historical revisions without S0 probes; ordinary revisions containing the probes need no overlay. The retained same-HEAD run uses this option because canonical Git metadata was mounted read-only, preventing the requested S0 commit. Both sides still use the identical HEAD product and identical read-only probes.

The orchestrator needs Linux, Node dependencies, and Python Playwright with Chromium. `--node` and `--python` override executables; `LAB_PYTHON` also overrides Python. The endpoint and node unit tests are portable. Products are extracted with `git archive`. `--head WORKTREE` (or the checkout path) measures the live tree, including uncommitted edits, instead of an archive. Each product has an exclusive temporary data root, random loopback port, built-in extensions enabled and updates disabled. Owner locks are checked on readiness and graceful shutdown. A browser is shared; every sample uses a fresh context at 1440×1000. Each side/scenario has one discarded warmup. A/B order is AB, BA, AB, BA, with paired bootstrap median differences from `benchmark-statistics.mjs` (2,000 resamples). No products, profiles or caches are written into evidence. Output directories refuse reuse.

`--scenario` accepts comma-separated `main,short,smooth,reasoning,continue`. `--matrix` runs these five required scenarios (main at least 10 samples, others at least 7). Individual dimensions can be selected with `--messages 100|2000 --tokens 500|3000 --smooth off|on --reasoning none|with --mode send|continue`. `--rate`, `--jitter` (0–1), and `--seed` control the fake stream. `--smoke` permits fewer samples for tool debugging; those are not acceptance evidence.

The fixture reuses `synthetic_rows` from `tests/browser-longchat-perf.py`, including its fixed visible tail. `power_user.chat_truncation=100` is verified in the browser, with exactly 100 history messages initially rendered. Generation uses the real custom chat-completion source, streaming enabled, and the normal Send/Continue handlers. Other product defaults, including `streaming_fps=30` and smooth-streaming speed, are retained and recorded per run. The provider uses exactly 500 or 3,000 cl100k_base tokens, 1–3 tokens/chunk, nominal 200 tokens/s, seeded ±25% interval jitter. UTF-8 decoding spans token boundaries. Optional reasoning precedes content using `delta.reasoning`, verified against the CUSTOM parser in `public/scripts/openai.js`. The custom backend in `src/endpoints/backends/chat-completions.js` forwards SSE through `forwardFetchResponse` in `src/util.js` without filtering delta fields; reasoning storage/rendering was checked in `public/scripts/reasoning.js` and exercised in the browser. `/models`, `/__requests` (bodies), and `/__timings` support external browser tests; parent callers also receive request/timing arrays.

All frame, typing, hook and LoAF summaries use the provider's first-chunk through last-chunk window. Durations and latencies are milliseconds; frame shares are percentages. rAF differences are rounded to 0.001 ms before threshold comparisons to avoid floating-point artifacts at exactly 16.7 ms. Raw samples preserve timestamps and scripts' `sourceFunctionName`, `sourceURL`, duration and forced-layout duration. LoAF attribution uses the browser-reported script name/URL: messageFormatting, DOMPurify, keyboard.js, or other. This API reports script entry points, not a complete nested CPU call tree: unattributed formatting/sanitizer work remains **other**, not an inferred zero cost. LoAF durations can overlap script durations and must not be summed as exclusive CPU time.

Formatting and `.mes_text` writes are timed separately in `StreamingProcessor.onProgressStreaming`; the reasoning hook covers the whole `ReasoningHandler.updateDom` block (including reasoning formatting). Scroll-call time measures synchronous scheduling, while later layout/scroll costs appear in frame/LoAF data. Updates/s counts measured DOM updates within the network stream window. The final render is intentionally outside that window. Smooth streaming can keep rendering after the last network chunk; finish latency includes that backlog.

First-token latency runs from provider receipt to the first visible generated assistant content/reasoning DOM change plus two rAFs. Finish latency runs from last data chunk to `CHARACTER_MESSAGE_RENDERED` plus two rAFs; both completion events are retained. Collapsed reasoning is excluded from first-token detection until visible answer text arrives. Two rAFs provide a paint opportunity, an upper-bound proxy rather than a compositor screenshot timestamp. A real Playwright `x` key is sent to the visible composer every 200 ms during streaming; keydown-to-two-rAF latency is measured in-page and filtered to the network window. Extra characters stay in the composer.

One second after the first DOM update, the live `#chat` is scrolled upward 600 px. The move is verified, and subsequent programmatic upward-to-bottom `scrollTop`/`scrollTo` writes are counted through final paint. Scroll probe writes themselves are excluded. Native scroll anchoring is not counted as programmatic stealing. This exercises the existing scroll-lock behavior without changing it. The worker targets the live chat and visible composer and rejects duplicate composers/chats. A worker-only setter removes the query flag immediately after the timing module reads it: otherwise jQuery UI treats fragment tabs as remote URLs against this page’s base URL and loads duplicate hidden page content. Probes stay enabled because the switch is read once.

Each sample has a small JSON summary and gzipped raw browser/provider samples; warmups are explicitly marked. `comparison.json` contains every metric's samples, median/p95, bootstrap intervals, paired differences and CI-zero checks. READMEs display medians of per-run values. Request bodies remain in the fake provider for lifecycle tests; S0 evidence retains only their hashes and synthetic generation metadata. Hostnames, loopback origins and local repository/home paths are redacted, including gzipped raw files.

The main decision uses the median per-run frame p95 and typing p95, with zero stolen scrolls required in **every** main run: frame ≤20 ms, typing ≤50 ms, scroll=0 → **skip S1 and S3, only S2**; otherwise **S1 then S2, S3 decided after S1**. These are headless Linux measurements; the later manual Windows check on the user's real chat remains separate.

S1 still updates chat fields and emits `STREAM_TOKEN_RECEIVED` on the existing per-chunk / `streaming_fps` schedule. DOM work (message formatting, the `.mes_text` write, the timer text, the reasoning block, and the follow-bottom scroll) is gated to one animation frame and then run in a task after that frame, so the animation callback itself stays short. Extensions reading `.mes_text` inside `STREAM_TOKEN_RECEIVED` may see the DOM up to two frames behind. When recent formatting averages more than 8 ms, the frame gap can add another frame or two; the finish paint is still an immediate full write. `stream_fade_in` keeps the previous synchronous morph. An unchanged reasoning block skips its DOM write.
