# 独立插件：命运之牌与好感度记忆

这两个插件可以分别安装、分别启用。ZIP 已包含前端源码、运行适配文件和许可证，无需为插件单独安装 Node.js 或 npm 依赖。

- **命运之牌**：聊天预设、命运牌、章节标记和跳转。已有 `/director` 快捷命令继续可用。
- **好感度记忆**：后台整理当前聊天中角色已知的事实、约定与关系倾向。扩展设置提供独立开关和整理频率；默认每 10 条有效角色回复整理一次，可改为 5 条。后台整理会调用当前连接的模型并消耗额度，界面不显示分数、等级或攻略提示。

兼容验证目标是官方 SillyTavern **1.19.0** 与本性能分支 **1.19.0**。具体通过的版本、场景和已知限制以随发布提供的验证报告为准。

## 手动安装

1. 备份现有酒馆数据。使用已内置对应功能的性能分支时，先在扩展管理中停用内置副本并刷新页面。
2. 下载需要的 ZIP，解压整个 `st-director-fate-cards` 或 `st-affinity-memory` 文件夹。
3. 放到酒馆目录下的 `data/<用户标识>/extensions/`。需要供全部用户使用时，放到 `public/scripts/extensions/third-party/`。二选一，同一插件只保留一份。
4. 确认扩展文件夹中直接包含 `manifest.json` 和 `index.js`，避免解压后多套一层文件夹。
5. 刷新酒馆页面，在扩展管理中启用第三方插件，再展开对应设置。

安装后的目录示例：

```text
data/<用户标识>/extensions/
├── st-director-fate-cards/
│   ├── manifest.json
│   ├── index.js
│   ├── runtime/
│   └── …
└── st-affinity-memory/
    ├── manifest.json
    ├── index.js
    ├── runtime/
    └── …
```

两个插件沿用已有设置和当前聊天中的数据。无需迁移聊天文件。当前完整酒馆仓库链接不适用于扩展面板的一键安装，请使用 ZIP 手动安装。

## 兼容行为

- 「命运之笔」更名为「命运之牌」；原 `/director` 命令、预设与聊天数据继续沿用。群聊 regenerate 不沿用导演指令；命运牌按群组作用域只注入一次。模板中随机、掷骰和计数器等宏在每次实际展开模板时重新求值；输入框里填写的宏字面文本仍按原文保存。
- 官方 1.19.0 会重新展开聊天第 0 条消息的宏。插件会在空聊天写入旁白时，或加载以 Director 消息开头的旧聊天时，添加一条空的系统起始标记。它不进入模型提示，启用插件时不显示；存档多一条消息。旧绑定和证据的物理位置一并调整，正文和逻辑 ID 不变。普通角色问候保持原生行为。
- 官方版本缺少的成功完成事件，由插件核对请求归属、模型响应、原生回复及成功保存后补足。停止、错误、工具调用中间结果和归属不明的请求均不授予成功凭据。群聊再生成适配原生 UI 与 `/regenerate`；其他扩展直接导入上游 `regenerateGroup()` 时，没有可观察的删除前信号，无法承诺沿用命运牌或逻辑回复凭据，仍按普通删除撤销旧绑定。
- 两个包各自包含完整兼容层，不读取另一个插件的文件。共用一个宿主时只协调一次事件观察与保存队列；独立包的拦截器名称也与内置版本分开，避免停用的内置 manifest 导致重复调用。
- 好感度后台整理只发送待评估证据、必要的既有记忆与结构化合同，输出预算独立且最多 2048 token。它跳过正文生成钩子和宏展开，也不套用可能覆盖消息的自定义请求体。命运牌抽牌仍使用原生 quiet 生成以取得当前故事上下文。
- 官方版本中，私密临时帧在世界书扫描期间使用不含正文的保留区占位；按当前 tokenizer 预留不少于最终正文的预算，组装后恢复原文。关闭、切换聊天、失败保存时不把过期状态写到新聊天。

可选的「随正文备牌」默认关闭：开启后，普通单人回复可同时备好下一组三张牌。合规的预生成事件按中档写作，中档选牌不额外调用模型；改选其他强度、模型未写出有效事件或仅备好牌面时，选择会再调用一次模型。它共用正文的输出预算，回复被截断时可能退回逐张生成。

正文、候选与思维字段中的备牌私密块会在保存前清除；官方宿主通过插件自己的保存适配处理，不需要修改官方源码。异步压缩跨过聊天切换时，以最多 128 条不含正文的来源戳清理已捕获的旧快照，不给过期生成授予成功凭据。存档里的 offer/log 元数据仍可能包含私密事件，隐藏不是加密。当前修复与实测范围见[备牌兼容修复报告](reviews/2026-11-08-fate-piggyback-fixes/README.md)。

真实模型的提取质量、各商业提供方与实体手机仍需要日常试用；本次浏览器验收使用本地合成提供方，不能据此保证所有模型的表现。

## 更新与卸载

手动安装的 ZIP 不提供 Git 自动更新。更新前备份当前插件文件夹和酒馆数据，再将新版本插件文件替换到原目录。卸载时先停用并刷新，再将对应插件文件夹放入回收站；保留聊天数据和其他扩展。

## 从源码构建

维护者在本仓库安装依赖后运行：

```powershell
node --test tests/standalone-plugin-package.test.mjs
node scripts/build-standalone-plugins.mjs
```

默认输出到 `.evidence/standalone-plugins/packages/` 下的一个新构建目录。每次构建保留以前的输出。也可指定保存目录：

```powershell
node scripts/build-standalone-plugins.mjs --output-dir .evidence/standalone-plugins/my-release
```

每个构建目录提供两个 ZIP、`SHA256SUMS.txt` 和 `build-report.json`。ZIP 内的 `build-info.json` 记录源文件和包内文件 SHA256；相同源码与构建器应产生相同 ZIP。源码包不包含宿主、用户数据、聊天、密钥、依赖目录、测试或备份文件。发布时保留 `LICENSE` 和完整性文件。
