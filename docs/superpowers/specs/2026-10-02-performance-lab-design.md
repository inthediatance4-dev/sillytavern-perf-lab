# 独立酒馆性能改进设计

选择本机独立完整应用副本与Git worktree。仅函数演示不能验证真实API；服务器并行副本会新增生产主机负载。当前方案可做真实HTTP/浏览器验证，并完全隔离现有服务。源基线为`db53872`，来源白名单与生产保护边界见根`ISOLATION.md`。

第一阶段保持请求与返回格式，进行四项内部改进：

1. 为搜索建立每文件独立、逐消息更新的关键词命中状态；词可分散在多条消息中，文件名兜底匹配保留。兼容`getChatInfo`的旧数组匹配回调。
2. 文件stat在正常async函数内执行；读取stream/line的错误、空文件、空尾行均完成或拒绝Promise。空行不计入消息数量，损坏的非空末行仍返回空对象。
3. 同一聊天文件按路径串行执行完整性检查、序列化及异步原子写入；失败释放队列但不影响后续写入。保持原来的备份节流。备份执行也按目录串行，防止同目录清理互相竞争；正常停机等待已触发的备份。
4. 自动聊天备份使用async扫描，每份候选只stat一次，排序后将过期副本移动到`.recycle`子目录。设置备份的旧接口不在此轮改造范围，避免扩大兼容变更。

新`src/chat-io.js`仅负责路径队列、异步原子写和可恢复备份维护；新`src/chat-search.js`只负责增量关键词匹配。`src/endpoints/chats.js`保留路由和格式适配。启动器只用`127.0.0.1:8770`及worktree内新数据，拒绝占用端口、外部路径和重解析链接，所有运行产物忽略。

测试先在原代码上重现搜索重复检查、空尾行和同步写入；再验证多关键词/文件名兜底、并发完整性校验、异常写入恢复、真实原子写、备份回收与计数。全部使用合成数据。最后运行同批函数基准、完整应用HTTP及浏览器验收，并只读核验服务器PID、重启计数和核心SHA。

不改整份聊天上传协议、角色统计缓存、模型请求、扩展逻辑或生产配置。性能结论限于本机合成基准，不外推模型生成速度。实现完成后保留独立分支和启动入口，不合并/部署。
