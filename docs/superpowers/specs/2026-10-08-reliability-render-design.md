# 聊天数据保护与长历史优化

2026-10-08，用户已授权“就按照你推荐的改吧，你来决策”。基于已交付 `cbb6208a72a01483992196e65651c733ba762adf`，在 `codex/sillytavern-reliability-render` 选择性采纳官方 1.19 修复，不整体升级。生产写入、重启和部署继续不在授权范围。

## 决策与边界

整体升级会同时触及供应商、扩展与现有独立改动；逐处补入经复现的修复更容易独立验收。本轮先做保护，再优化客户端重复工作。保留现有异步 IO、多路径锁、独占创建、退役/回收、默认提示词及聊天直达。所有删除内容进入回收区；测试夹具不清除。只使用新建人工数据，不读真实聊天或模型。

## 1. 文件头与降级预览

完整性检查启用且请求提供 integrity、未 force 时：空/不存在文件可写；可解析 legacy 对象继续兼容；非空坏 JSON、null、数组、primitive 文件头拒绝写入，BOM 剥离后比较真实 slug。保持现有响应与冲突处理，原文件字节不变。尾行截断的历史仍显示降级预览，保留路径、元数据与有效匹配，排除未读完整的尾行。保留流式 matcher、空白行处理、stream error 和 recent 的版本缓存契约。并不保证 force 或缺少 slug 时的完整性，也不宣称修复整个文件内容。

## 2. 备份隔离与容量

节流身份按用户和规范化具体聊天文件路径区分，同角色历史和群聊历史各自独立。保留每份历史的 leading/trailing 最新快照合并，但不能让其他文件吞掉备份。新文件名仍能被现有备份浏览器发现；以原始名称/历史身份哈希区分中文名称和同角色历史的清理配额。原有备份不改名、不自动迁移或永久删除，仍可浏览与恢复。

调度状态默认最多 256 个注册键、绝对/闲置清理在调用时发生；不得形成按访问历史无限增长的 Map。容量淘汰之前必须 flush 等待的快照并等待已开始的写入，不能以 cancel 丢弃数据。可以在容量全忙时直接写入而不长期注册，需明确并发写入与生命周期 flush 的边界。每个键避免同一异步回调重叠，pending 只保留最新快照；正常关闭等待调度与现有 IO。无新增依赖。限额回收仍用既有 .recycle；备份浏览器的删除接口也改为持有目录/文件锁后回收，保留成功/未找到/非法前缀的 API 契约和可恢复字节。

## 3. 长历史的格式化深度计算

先测现有渲染流程。优先以无全局缓存的尾部计数替换每条消息都建立完整 `chat.map/filter/findIndex` 的深度计算：仅统计目标之后的非 system 消息，保持原有 messageId 转换、系统/瞬时消息及 regex depth 语义。可显示最后 100 条时，将整份历史扫描/分配改成尾部处理；无改变 Markdown 清洗、消息数据、顺序、扩展事件、提示词或 DOM 接口。用参考算法和操作计数证明语义相同及减少工作，并在真实浏览器人工长历史复核。若实际热点另在解析/插件，记录剩余阻塞，不能将复杂度优势写成未测秒数。分帧渲染和完整在途响应控制留待另项验证，避免引入新的切换竞态。

## 4. 向量批数量

已复现 WebLLM/KoboldCPP 在每批遍历全部 texts，21 输入产生 63 输出。本轮限定批内读取，结果顺序与输入一一对应；覆盖 0/1/10/11/21/大批，不调用供应商或写真实索引。缺失向量行为需明确兼容原接口，不能额外改变远程后端、事务或模型生命周期。
